# PortraitFrame: Development Journey (발자취)

본 문서는 프로젝트가 어떻게 진화하고 어떤 기술적 장애물을 극복했는지 기록한 히스토리입니다.

## Phase 1: 1440x3440 디지털 액자의 탄생
가장 먼저 PyQt6를 이용해 1440x3440 세로 해상도에 딱 맞는 로컬 이미지 뷰어를 개발했습니다. 이미지 전환 효과(Transition)와 캐싱 로직을 구현하여 "가볍고 빠른" 디지털 액자의 기초를 다졌습니다.

## Phase 2: 수집기(Collector)의 병합과 분리
처음에는 뷰어 프로그램 내부에서 타이머를 돌려 인터넷에서 사진을 다운로드하는 방식을 고려했습니다. 하지만 이미지 리사이징, 해시 연산 등 수집 작업이 뷰어의 렌더링 리소스를 뺏어 프레임 드랍을 유발할 수 있다는 점을 깨달았습니다. 
이에 따라 수집기를 독립적인 Python CLI 프로그램으로 완벽하게 분리하여, 수집기는 터미널에서 '곡괭이'처럼 자원을 캐고 뷰어는 로컬 파일만 가볍게 띄우는 이원화 아키텍처가 확립되었습니다.

## Phase 3: API 연동과 장애물 극복
- **Unsplash, Pexels, Wallhaven:** 각 플랫폼의 공식 API를 연동하고 멀티스레드 기반 다운로드 파이프라인을 구축했습니다.
- **ArtStation의 403 Forbidden:** 웹 크롤링을 시도했으나 ArtStation 측의 강력한 봇 방어(Cloudflare)로 인해 지속적으로 403 에러가 발생했습니다. 헤더 우회 등을 시도했으나 안정성 문제로 최종적으로 해당 소스는 비활성화(Deprecated) 처리하는 현명한 결정을 내렸습니다.

## Phase 4: "손상된 이미지" 위기 (The Broken Image Crisis)
컬렉터가 대량의 이미지를 수집하던 중, 네트워크 스트림이 끊겨 아래쪽 절반이 회색으로 렌더링된 "반쪽짜리 사진"들이 수집되는 심각한 버그가 발생했습니다.
- **원인:** Pillow(PIL) 라이브러리의 `LOAD_TRUNCATED_IMAGES = True` 설정 때문에 손상된 스트림을 오류 없이 강제로 저장해 버린 것이 원인이었습니다.
- **해결:** 해당 옵션을 즉각 비활성화하고, 이미 수집된 2,016장의 사진을 전수 검사하는 커스텀 수학 스캐너(`scratch_find_broken.py`)를 개발했습니다. 밑바닥 20픽셀의 표준 편차(Variance)가 0에 수렴하는 이미지를 정확하게 식별하여 총 262장의 불량 사진을 오차 없이 색출 및 격리(Purge)하는 데 성공했습니다.

## Phase 5: 최종 패키징과 보안 (Production Ready)
- **Mac App Bundling:** 프로젝트를 다른 Mac으로 AirDrop하여 쉽게 실행할 수 있도록 `PyInstaller`를 사용해 `.app` 번들로 컴파일했습니다.
- **Iconography:** AI를 활용해 1440x3440 초광각 모니터의 아이덴티티를 살린 '꽉 찬 화면의 세로 모니터(Full-bleed)' 아이콘을 디자인하여 `.app` 파일에 이식했습니다.
- **Auth Closure:** 하드코딩된 API 키들을 `.env` 환경 변수 파일로 분리하여 소스 코드의 보안성과 배포 편의성을 상용 소프트웨어 수준으로 끌어올렸습니다.
